# RoleAide product contract

Owner clarification, October 29, 2026. This supersedes earlier account gating and the deferred-builder scope.

| Page | Access | Required outcome |
| --- | --- | --- |
| Jobs and applications | Guest or signed in | PDF/DOCX/image/pasted CV → editable extracted profile and preferences → related real listings → explained percentage → editable copy/download cover letter → original application page. No sign-in prompt blocks these actions. |
| CV builder | Signed in | Create/optimize/import and edit a CV, guided choices with editable regional details, review and export, save current/previous versions. Guests see sign-in/sign-up before editor tools. |
| Workspace | Signed in | Owned saved CVs/versions, owned applications and their recorded statuses, associated role/skills/letter evidence. Guests see an invitation to sign in. |

Authentication is email/password sign-in, sign-up and password recovery; Google is shown when the actual provider is enabled. Confirmation and recovery emails are account-security steps, not prerequisites for guest job tools. Opening a confirmation on a phone does not sign a separate PC into the same account; users sign in on each device using their credentials.

Tracking is optional. Opening a listing is not a submitted application. Submitted/interview/offer states are candidate reports, never claimed employer observations. No access to an employer's applicant pool is implied. Match percentages describe available text evidence, not hiring probability; no letter can guarantee consideration.

Guest provider access uses durable shared limits and a global allowance plus cached job results. Server-only credentials never go to the browser. A quota failure offers retry/public browsing, never a forced login. Private workspace records stay behind ownership policies.

No new subscription or production/auth/schema change without the existing notification rules. Real provider, account delivery and deployment acceptance remain distinct from mocked tests.
